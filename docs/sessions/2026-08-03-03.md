## 2. Issue #18 — and why the issue was wrong

Filed as a wording nit on SERP queries. Reproducing it found the real cause
somewhere else and worse.

`locations` was consumed as `locations[0]` verbatim. A model asked where a
company operates answers with whatever the site says, and wise.com's site says
`['160+ countries', 'United Kingdom', 'Estonia']` — the marketing claim first.
So **three of ten scored prompts** went out as *"Who are the leading Relocating
internationally companies in 160+ countries?"*. Four paid calls each, on
questions nobody would ask, feeding the GEO score the product sells.

`primary_location` now skips coverage claims to the first entry that names a
place, and both surfaces share it. Also `in the United Kingdom`, and search
topics lowercased the way people type them with acronyms preserved.

**Measured honestly: the SERP score did not move** (3/6 before and after). The
issue's premise — that query form was depressing the score — was not supported,
and the issue now says so. The value was the wasted paid questions.

## 3. Issue #16 — the safety net that was not there

The api booted with `alembic upgrade head && uvicorn ...`. `AUTODEPLOY.md`
already warned a *broken* migration could not be undone. The sharper half: a
**successful** one could not either. Once the DB is stamped at a revision the
previous image never heard of, that image's alembic exits 255, `&&` stops
uvicorn, `unless-stopped` crash-loops it — and `rollback.sh` never downgrades.
The recovery path was the thing that failed, and every migration since `0002`
armed it.

Prod now serves only; both drivers migrate first, before any container is
replaced. Proven rather than argued: same DB at 0007, same pre-0007 image, the
old fused command dies on `Can't locate revision identified by
'0007_serp_visibility'` and the new one boots in 4s and **serves a real row
whose five extra columns it does not model**. It was never the ORM — SQLAlchemy
maps only declared columns — only alembic's boot-time guard.

Verified live: the deploy logged `4/7 migrate → schema migrated to head`, and
production's api command is now `["uvicorn", ...]`.

Two things it does **not** fix, stated in the ADR and the PR: destructive
migrations, and `rollback.sh`'s pruned-image branch, which `git checkout`s the
old compose file and so re-arms the bug until `.last-good` moves past this
change.

## 4. The SEO audit

The GEO score says whether AI engines name a company; SERP says whether search
results do. Neither says **why** — and why is the only part a customer can act
on. `discovery` was already crawling six pages and discarding all the structure,
so the audit is a second reading of a crawl already paid for, plus one fetch of
`/robots.txt`.

**The two checks worth having built it for**, neither of which a classic SEO tool
performs:

- **`ai_crawler_access`.** A site whose robots.txt blocks the crawlers answer
  engines use cannot appear in their answers — absent by construction, not by
  ranking. It separates *retrieval* crawlers (blocking costs answers today) from
  *training* ones (erodes presence over time), because telling someone their
  visibility is broken when they merely declined to be training data would be
  alarmist. `Googlebot` counts as retrieval: Google documents it as the control
  for AI Overviews, with no separate opt-in. `Perplexity-User` is reported and
  never scored, because Perplexity says it ignores robots.txt and claiming
  otherwise would be false.
- **`server_rendered_content`.** Most AI crawlers do not run JavaScript, so a
  client-rendered SPA is invisible to them with robots.txt wide open. Discovery
  already knew — it is what triggers the bundle fallback. The audit says so.

**The headline is a grade, not a score, and the grade is capped.** `geo_score` is
a measurement; an audit score is a rubric whose weights are editorial. Worse, a
weighted average averages a fatal problem away: a site that is `noindex` *and*
blocks every AI crawler can bank enough minor passes to look like a C. One
critical failure caps at C; two cap at F. That rule is published, not hidden.
