## 1. What this session was

The operator asked for discovery, KYC and prompt generation to be taken from MVP
to production grade, with a written plan first and the implementation in the
same PR.

The plan is `docs/pipeline-quality-plan.md`. It starts from one observation: all
three steps fail *silently*. A crawl that reads six copies of the footer, a
profile with an invented product, and a question about "payload capacity" all
produce the same thing — a confident GEO score. So the plan is organised around
what the pipeline is **entitled to believe**, in three workstreams (D discovery,
K KYC, P prompts).

## 2. What changed

**Discovery (`pipeline/discovery.py`)**

- Decode by the encoding the page declares: header charset, then `<meta charset>`
  in the first 2 KB, then httpx's default. Without the middle step a
  windows-1254 Turkish page arrives as mojibake nothing downstream can undo.
- Sniff the first bytes for binary magic numbers (`%PDF`, zip, PNG/GIF/JPEG,
  gzip, RIFF, PostScript, or a NUL in the first 512). This is what closes
  tech-debt #28 without abandoning the deliberate fail-open on a missing
  Content-Type.
- Retry the homepage **once** on a transport error. It is the one fetch whose
  failure ends the job.
- Score links (path keywords + anchor text, minus feed-ish paths, minus depth)
  instead of a boolean substring test; drop never-descriptive paths (login,
  cart, privacy, careers) and non-document extensions outright; strip fragments
  before de-duplication so `/about` and `/about#team` are one page.
- Extract visible text as **blocks** and drop a block already seen earlier in the
  crawl, plus a per-page cap on pages after the homepage. Sites repeat their
  header/footer/legal blurb on every page; keeping the first copy loses nothing.
- Tighter SPA literal filtering: unambiguous JS tokens and framework diagnostics
  are rejected. Measured live on `beyondtech.com.tr` — see §5.

**KYC (`pipeline/sanitize.py` new, `pipeline/kyc.py`)**

- One **normalized key** (folded, casefolded, punctuation-free) shared by
  dedupe, grounding containment and brand-leak detection, built on the existing
  `textfold.fold`. If those three disagreed, a name could ground under one
  spelling and leak under another.
- Every field sanitized before anyone reads it: trimmed, unwrapped, junk-filtered
  (`"N/A"`, `"unknown"`, `"-"`), de-duplicated case- and diacritic-insensitively,
  capped per field; the company removed from its own competitor list.
- **Grounding**: a `product`, `competitor` or model-supplied `alias` that does
  not appear in the crawl is dropped. Narrow on purpose — the inferred fields
  (`description`, `industry`, `keywords`, `category`, `use_cases`) are meant to
  be the model's own words, and the minted aliases are facts about the
  submission. Skipped below `MIN_GROUNDING_CHARS` (1 000) and off for checker
  rows, whose "source text" is a sentence the runner composed.
- Two new defaulted model fields: `category` and `use_cases`.
- The single retry now leads with a repair instruction (still carrying the
  literal `JSON object` phrase `MockProvider` keys off).
- `require_usable` counts the new fields as topic signals and junk-checks every
  candidate itself.

**Prompts (`pipeline/prompts.py`, `pipeline/checker_prompts.py`)**

- A typed, filtered, ranked topic pool: `category` → `use_cases` → filtered
  keywords → short services → industry, with a filter that rejects phrases that
  cannot be a category (digits, spec symbols, attribute tails, bare hyphenated
  adjectives).
- Phrasing by topic **kind** and **number**: manufacturers / providers /
  companies decided by the head noun, and "the best tactical UAVs available"
  vs "the best warehouse automation *options* available".
- Rotation that actually covers: category and topic advance on different
  strides, so six topics now yield 36 distinct questions instead of 6.
- **Hard invariant:** no prompt outside `brand-probe` may contain the company
  name or an alias. Enforced on the topic pool and re-checked on the finished
  text.
- The checker set shares the same topic pool; its 12 templates are untouched.

**Frontend** — `KYC` gains `category?` / `use_cases?` (optional: rows persisted
earlier have no such key) and `KycCard` renders both.

## 3. Assumptions recorded

- **`MIN_GROUNDING_CHARS = 1 000` is reasoned, not measured** (tech-debt #33).
- **The category filter cannot be complete** (tech-debt #32). `"fiber optic"`
  passes it and is still not a category; a legitimate `"5G antennas"` is
  currently rejected by the digit rule. The real fix is `KYC.category`.
- **Grounding is the right default for crawl rows** on the argument that the
  model can only have seen the text we sent it, so a proper noun that is not in
  that text was invented. If a real run shows this dropping genuine products,
  the fix is the tolerance, not the principle.
- **Turkish stays parked.** Steps 2b and 6 of `discovery-kyc-improvements.md`
  are untouched; everything here is language-neutral. `test_footprint.py` still
  pins that `Yankinin` does not match `Yanki`.

## 4. Cost

**No new paid call on any path.** The KYC step still makes exactly one provider
call on the happy path (one bounded retry on failure, as before), and prompt
generation is still deterministic and free. Tech-debt #27 (KYC-stage spend is
invisible to every cost control) is untouched and unwidened — which is also why
LLM prompt generation was rejected here rather than built.

## 6. Current state

- **Implemented:** all of workstreams D, K and P (see §2).
- **Incomplete by design:** LLM prompt generation, KYC-cost accounting,
  sitemap-aware crawling, concurrent crawling — each with its reason in
  `pipeline-quality-plan.md` §7.
- **Blockers:** none. The branch needs review, then a PR into `main`.
  **Merging to `main` auto-deploys to production.**
- **Contract impact:** none (zero-diff `gen-types`, no migration — `kyc` is
  schemaless JSONB, no `VERSION` bump).
- **Behavioural changes to watch on the first live day:** hallucinated products
  and competitors disappear from `KycCard` (they were never real); a profile
  whose only topic signal was a placeholder now fails the usability gate rather
  than buying 60 calls about "solutions"; and prompts stop naming the brand,
  which — for any site whose keywords contained it — will *lower* the reported
  GEO score. That last one is a correction, not a regression: those prompts were
  scoring the brand against itself.
