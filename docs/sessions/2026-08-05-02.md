### 1.5 A loaded gun found on the way in — repaid before P7.1 touched it

P7.1's deliverable is a migration, so the first thing checked was whether the
migration chain is currently sound. It was not. Against a clean, fully-migrated
Postgres, **`alembic check` failed**: eight indexes exist in the migrations and
in production, but were never declared on `Base.metadata` —

| table | migration-only index |
|---|---|
| `analyses` | `ix_analyses_status_created`, `ix_analyses_checker_reuse` |
| `serp_checks` | `ix_serp_checks_analysis_id` |
| `seo_checks` | `ix_seo_checks_analysis_id`, `ix_seo_checks_check_id_status` |
| `checker_submissions` | `ix_checker_submissions_analysis_id` |
| `site_audits` | `ix_site_audits_project_created_at`, `ix_site_audits_queue` |

Autogenerate compares a live database against the **models**, so an index that
lives only in a migration reads as one the models want *dropped*. The next
routine `alembic revision --autogenerate` — precisely what P7.1 calls for —
would have emitted eight `op.drop_index(...)` calls, and merging that
auto-deploys. The two that would have hurt most are the site-audit queue index
and the checker 24h-reuse index. Nothing caught it because every test builds
its schema with `Base.metadata.create_all`: the models were the only definition
under test, so test databases and production had quietly different schemas.

Repaid in `aa0c80c`, additively: the eight are declared on the models. **No
migration changed and no production DDL runs** — the indexes already exist
there; what changed is that the models now admit it, and SQLite test databases
now build the same shape production has. `alembic check` is clean.

A guard came with it — `backend/tests/test_migrations.py`, the first test in
this repo to exercise the migration chain at all: `upgrade head` from empty
builds exactly `Base.metadata`'s tables; `alembic check` finds no drift;
`downgrade base` reverses the whole chain (ADR-30's rollback concern, one layer
lower). Postgres-only, skipped when `TEST_DATABASE_URL` is unset, so the
default `uv run pytest` stays hermetic. Suite: **488 → 491 backend**.

One incidental change rode along: `ruff format` collapsed a `GeoRecord` line
that PR #11 left unformatted. That the file could sit unformatted on `main` at
all is its own finding — CI gates `ruff check` but never `ruff format --check`
— recorded as tech-debt **#57** with the fix deliberately left to its own PR.
