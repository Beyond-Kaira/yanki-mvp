## 3. Architectural changes

**ADR-28** in `design.md`. The two decisions worth re-reading before touching
`lib/session.ts`:

- **The access token is module state and the module refuses to run on the
  server.** Module state on the server is shared by every request that renders,
  so one visitor's token would become everyone's. `setAccessToken` throws outside
  the browser to make that structural rather than a convention.
- **Rotation needs both guards, and they are not the same guard.** The in-tab
  promise stops one page's callers from racing. The Web Lock stops *tabs* from
  racing, which is the case that actually signs people out, because refresh
  rotation is single-use and the backend revokes the family on replay.

## 8. Merged against `main` mid-session — a numbering collision, corrected

The branch was 8 commits behind `origin/main` (`df35e87`, PR #14 — pipeline
quality). Rather than leaving the divergence to be discovered at review or at
merge time, `origin/main` was merged into `feat/auth-screens` (`git merge
origin/main --no-edit`, ordinary merge, **not** a rebase — the branch is
already pushed and reviewed, and rebase would rewrite the commit hashes the
review's inline threads point at).

The merge was clean in code — `frontend/lib/contracts.ts` auto-merged (main
added `KYC` fields, this branch added `SignupCredentials`) — but **conflicted
in the two docs files this session had just written**, because main's
concurrent session (2026-08-01, P5.15, `sessions/2026-08-01-01.md`) had
independently claimed the same identifiers:

| | main (2026-08-01, landed first) | this session (had written) | resolution |
|---|---|---|---|
| ADR | ADR-27 (pipeline quality part two) | ADR-27 (session layer) | this session's ADR is now **28** |
| Session number | "Session 15" (P5.15) | "Session 15" (P6.1) | this session is now **16** |
| tech-debt | #30–33 | #30–34 | this session's items shifted to **#34–38** |
| Session log filename | `2026-08-01-01.md` | `2026-08-03-01.md` | no collision (different dates) |

Every cross-reference to the shifted numbers was found and corrected: within
`design.md` and `tech-debt.md` themselves, in the P6.1 card and the Current
Priority entry in `implementation-plan.md`, in the §2d status note in
`roadmap.md`, and throughout this file. Main's own #30–33 and its ADR-27 were
left untouched — they were never wrong, only unaware of a branch that had not
yet merged.

**Lesson, generalized:** a branch that sits open across other PRs merging to
`main` will collide on anything both sides number sequentially — ADRs, session
logs, tech-debt items, phase/session counters. The fix each time is mechanical
once found, but finding it requires actually diffing against current `main`,
not assuming the branch's view of "the next number" is still correct.
**Going forward: before starting work on an existing branch, fetch and check
its position against `origin/main` first** (`git fetch origin main && git
rev-list --left-right --count origin/main...HEAD`), and merge main in early —
before writing anything that claims a shared sequential identifier — rather
than after, when the collision has to be untangled from finished prose instead
of avoided.
