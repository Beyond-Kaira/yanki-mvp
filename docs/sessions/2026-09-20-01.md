# Existing GEO industry ranking — first part

User approved using stored GEO sector labels across all organizations, without
manual per-question classification. Brand-probe questions are excluded. This
supersedes the independent question-generation flow, which remains in the dirty
worktree until separately approved UI/API replacement. No commit or deployment.

Added only two code files: `backend/app/industry_citations/ranking.py` and
`backend/tests/test_industry_ranking.py`. Existing application code was not
changed. Reused canonical URL, search-result rank/inline-marker evidence and
run-provenance helpers without modifying them. No API, worker or migration added.

The internal read-only query joins GEO rows to responses and analyses across
organizations. It requires matching analysis ownership of the response, counts
each response once per page/hostname, and merges identical question text across
runs after Unicode/case/whitespace normalization. Successful uncited answers
remain in the denominator. Sorting is response count, question count, then URL
or hostname. Exact hostname grouping and conservative URL canonicalization are
explicit in the report. Output excludes customer IDs, brand, question/answer
text and search result titles; it includes citation URLs and aggregate counts.

Validation: 9 tests passed, Ruff passed, mypy passed, whitespace check passed.
Tests cover cross-org aggregation, repeated-question deduplication, multiple
pages/citations in one answer, uncited denominator, sector labels rather than
semantic classification, brand/unknown/mock/error exclusions, fabricated URLs,
missing inline markers, output boundaries and empty reports.

Executed against the local PostgreSQL database in a READ ONLY transaction:
99 e-commerce candidate records, 4 brand probes excluded, 65 unknown-provenance
records excluded, 30 eligible answers, 10 distinct questions, 36 pages, 34 sites.
22 citations lacked inline markers and were rejected. Leading sites: ensun.io
and www.cbinsights.com each 4 answers/2 questions/13.33% coverage; www.eshipz.com,
www.productsup.com and www.skycomcallcenter.com each 3 answers/1 question/10%.
No new LLM calls or database writes were performed.

Limitations: legacy provenance review is outstanding; missing flags do not prove
simulation, and old records must not be silently promoted to live. Current query
streams all GEO records and filters normalized sector labels in Python; large
datasets need indexed normalized labels and bounded/paginated result retrieval
before public API exposure. No cross-org question/answer evidence endpoint is
authorized by this implementation. Sector-level metadata can include mixed
question topics, as explicitly accepted by the user.

Documentation: updated current scope, implementation plan and operator handoff;
retained superseded sections as history. Unrelated files were not removed.
